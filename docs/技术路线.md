# 技术路线

产品主路线就是下面四张图。实现细节（Rust 内核 + Claude Code）服从这条线，不反过来改写它。

自建与 FAQ 见仓库 [README](../README.md) 和 [DEPLOY.md](DEPLOY.md)。

## 1. 核心架构 — claude2api

![Console API 取代 OAuth](images/vm2api-01-console-api.png)

**claude2api** 采用独家 Console API。

- Setup Token 转换为 Console 可用 API
- **取代** OAuth 获取的 AT / RT
- 让 Claude 认为你是 **Console API**，而不是 OAuth
- 从而实现 **0 提示词注入**

不再靠改 system / 注入人设去“像官方”。身份在凭证形态上就已经是 Console。

```text
Setup Token ──转换──► Console API ──► Claude 按 Console 客户端看待
OAuth AT / RT  不再作为主凭证
提示词注入     不做
```

## 2. 请求怎么走

![六站技术路线](images/vm2api-02-route.png)

| 站 | 做什么 | 不做什么 |
|----|--------|----------|
| 用户请求 | 收 Anthropic / OpenAI 兼容入口 | 不直连 Anthropic |
| 协议清洗 | 对齐 `/v1/messages` 可转发形态 | 不注入产品提示词 |
| `POST /v1/messages` | 控制面入口 | 不在 Node 里发推理 |
| Claude Code 原生 subagent | 槽内官方转发面 | 不用第三方假客户端顶替 |
| TCP 转发 | 槽内打到 Console API endpoint | 不把 OAuth AT/RT 当主 hop |
| 透明回传 | 原样给用户 | 不改写业务回复 |

```text
用户请求 → 协议清洗 → /v1/messages
       → Claude Code subagent → TCP 转发
       → Console API endpoint → 透明转发给用户
```

## 3. 虚拟机

![虚拟机与 20 路 subagent](images/vm2api-03-vm-subagent.png)

- 运行时：**Docker** 或 **真虚拟机**
- 转发面：虚拟机内 **Claude Code 原生 subagent**
- 并发：最大 **20**
- 指纹：要拟真 **物理机指纹**
- 部署：Compose **只起控制面** `vm2api`；每个已启动槽再起一个宿主机容器 `kin-<槽>`。不是父容器里的多进程

物理机指纹是正在攻克的问题。欢迎开 Issue / PR 提供方案（TPM、SMBIOS、网卡/磁盘序列、传感器噪声、电源/热曲线等）。没有稳定方案之前，文档不假装已经完成。

## 4. 遥测

![全量遥测与独立电脑](images/vm2api-04-telemetry.png)

- 遥测 **全量发送**
- 目标：Claude 认为你是一台 **完全独立的电脑**
- 并且 **无其余特征**（不带网关集群、多槽、面板的额外指纹）

一槽一台机器。身份、遥测、指纹都按单机收敛。
