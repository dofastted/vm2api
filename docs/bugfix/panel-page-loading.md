# 管理台路由加载审计

## 问题与可重复证据

通用路由错误组件原先将任何异常都标为 `500`。在真实生产构建的本地受控实验中，动态 JS 分包首次加载失败会先显示该错误页，然后路由库的既有模块重载机制刷新文档，第二次加载成功后进入目标页。单纯延迟分包 2–5 秒没有触发通用错误页。

这说明 UI 中的 `500` 不足以证明服务器返回 HTTP 500。实验能复现页面行为，不足以认定任何线上故障的网络、代理、缓存或部署原因。

修复给路由等待提供明确加载提示，并将资源失败、API 请求失败和组件异常分别呈现。不会将真实异常渲染为成功页面；错误页提供显式重新加载按钮。

## 本地复现与回归

先按项目现有方式安装依赖并构建前端。运行工具前必须已有 Playwright 模块和可用浏览器；工具不会安装依赖或浏览器。

```sh
npm --prefix web run build
node scripts/audit-panel-routes.mjs --dist web/dist --output panel-route-audit.json
```

如果 Playwright 不在项目模块查找路径中，可通过 `--playwright` 指定其模块路径；通过 `--channel chrome` 使用已安装的 Chrome。未指定 channel 时由 Playwright 选择默认 Chromium，可执行文件不存在时明确报错。

该脚本只启动随机本地端口，阻止发往其他 origin 的请求，使用独立浏览器上下文、虚构身份和显式返回 503 的业务 API。没有真实凭据，也不访问生产服务。JSON 报告逐项记录断言，任一断言失败时进程非零退出。

## 覆盖矩阵

| 范围 | 冷启动入口 | 分包延迟/失败注入 |
|---|---|---|
| 总览、集群、虚拟机列表、导入、规格、计费、代理、模型、system、密钥、API、Anthropic、统计、数据库、用户、内核 | 逐项运行 | 不逐页注入 |
| 风险审计、日志 | 逐项运行 | 两页分别运行 |
| 设置入口 | 验证转向 sticky | 不单独注入 |
| 设置 sticky/pool/quota/openai/logs/protocol/redaction/init/health/notify/telemetry/socks5/backup/about | 14 个页签逐项运行 | 共用 `_tab` 分包，仅 sticky 注入 |
| VM 详情 | 虚构 ID 入口 | `_id` 分包独立注入 |
| 根入口、登录、欢迎页 | 逐项运行 | 不逐页注入 |

当前原生上游合计 37 个冷启动入口和 8 个分包注入场景。

冷启动断言包括最终路由、非空内容、没有整页通用异常、没有未捕获 JavaScript 异常。故障注入额外检查：确实拦截到目标分包；延迟时出现 pending；失败时出现资源失败分类；没有旧 500 文案；最终到达预期 URL 且目标页面或数据错误容器真实出现。设置与 VM 的断言限定在 `main` 内容区，并匹配目标 API 路径专属的错误消息，避免把起点页面或全局 toast 的错误当作目标已挂载。只检查“500 消失”是不充分的。

另用受控浏览器验证了分包连续失败两次：错误页保留“页面资源加载失败”，在连接恢复后点击“重新加载”进入目标页。该手动恢复专项不是当前脚本的自动化断言。

## 覆盖限制

- 业务 API 503 是测试条件，不是被发现的产品缺陷。
- 此审计验证路由加载和错误隔离，不验证业务数据、提交按钮、付费、权限组合或真实 VM 操作。
- 设置 API 返回 503 时，数据门禁不挂载内部表单；14 个入口通过不代表内部表单全部验证。
- VM 详情仅验证路由和数据错误容器，没有验证 overview/account/proxy/test/ops/seed 内部页签。
- 下游部署的独立门户、注册、分组、兑换码、接入指南和模型广场定制不属于当前上游代码范围，不能把下游 49 入口矩阵与上游 37 入口混称。
- 入口清单显式维护，新增路由或设置页签时应同步脚本。
