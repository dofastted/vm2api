# 原生 CRAG 面板适配：复用入口整流

接续[最简交付与历史复用实验](crag-panel-history-reuse.md)。不改 CRAG、官方 CC、载荷、调度或公共协议。普通原生回合走「公共入口生成结构化 Messages → 槽位调整 → 校验、脱敏并发送」；面板不预造最终供应商请求。

## 两步对照

1. **只省重复整流。** 认证 health 同时声明 `generation_controls_v3` 和 `linux_tui_native_queue`、入口已是规范历史且保持工具原名时，`toStandardAnthropicBody` 从两次降到一次，取消该分支的末次客户端文案与工具名整流。非规范历史、兼容槽、修复重试、官方 body 透传、cwd 投影和摘要保留旧整流。原生图片别名处理、槽位 system 策略、缓存和起始预算仍生效；运输前仍检查块结构及嵌套工具结果，并将结构验证与可复用判断合并。无远程图时不再给每个块创建异步任务。这里的一次指标准化函数，不是整条链只遍历一次请求。
2. **只省旧信封头。** 通过认证 health 识别的原生队列，在普通 `cliHop` 的 Worker POST 中省略整个 `headers` 对象及其构造、协议 beta 扫描。受信 classifier、thread、标记为 `repaired` 的重试、旧槽及预构建信封保留原路径。真实 HTTP 的内部 token、可信租户和内容类型不变；日志仍分别记录面板 envelope 与最后实测出站头，不用缺省值冒充出站值。CRAG `79c73d5` 仅在 classifier 解析该头包，普通推理由 CC 构造上游头。

vm2api 根据 typed blocks 确定工具结果边界，并保持块边界稳定以便复用缓存。结构化调用 ID、结果、结果后的用户正文和图片均原样保留，不拼接成文本或补充提示。

## 认证回环等价

`system` 的单个文本对象与单元素数组按相同规则处理。遇到前导系统指令时，先保留顶层文本及其缓存断点，再按顺序追加前导指令，不把同一份顶层文本写进用户消息。非文本块或非字符串正文不能无损转换，返回包含字段路径的请求错误。这是结构约定，不是上游计费或成功率判据。

使用 CRAG `79c73d5`（3.1.4）、官方 Linux x64 Claude Code 2.1.321（SHA-256 `426c33815ca6645a772f722fbff10dbf2cbdb124a8aeab733c1365dbf8bbf61f`）。网络命名空间只启用 `lo`：入口 fixture 认证 → token/租户绑定 Unix socket → 原生 TUI → 模拟 OAuth 的 TLS 回环。没有调用真实供应商或执行客户端工具。

## 缓存观察

100 对文本轮按 JSON/SSE 各半，双方 caller `1h` / `5m` 断点的实际出站前缀相同，模拟读/写及分 TTL 用量均原样交付。模拟向前检查 20 块：只规范化 CCH，98 次最深到 system；另去掉原生计费块，99 次最深到 system；两种模型都 **0 次**复用到 messages。旧尾锚点随对话推进、原生提醒位置随续接变化，A/B 一致；因此本次面板减负没有修复原本的消息层缓存限制。隐式 TTL 的面板交付另在既有集成测试断言，不能由此推断所有原生请求都保留省略状态。

重基后缓存边界 **12/12** 等价：固定旧消息锚点后有消息层复读，超过 `5m` 只到 system，超过 `1h` 全冷，改变业务 system 后只到更浅的 system 前缀。第一次基线在回收重叠时看到两个 CC PID，未将该轮计作通过；复测检查观察到官方进程并以回环接收端的一次 POST 作为实际执行计数，不以进程数估算调用数。该组验证的是夹具的过期与前缀模型，**不代表 Anthropic 缓存命中或计费**。

## 面板性能

对 `328f4b56`，同一协议 handler、认证 Unix socket fixture、WSL2/Node 24.13.0。固定一个 CPU，轮换每组三种配置的启动顺序，每种配置共三次独立进程。下表是复测的三组分位数中位数；每组每配置每负载 4 轮，每轮预热 15 次、计量 100 次，共 14,400 次计量。CPU 含同进程 fixture、传输及 GC，不含原生进程启动或模型生成。

| 负载 | CPU p50：基线 → 两项优化 | CPU p95：基线 → 仅省整流 → 两项优化 |
| --- | ---: | ---: |
| 短文本 | 2.865 → 2.632 ms（−8.1%） | 4.805 → 4.649 → 4.949 ms（+3.0%） |
| 约 270 KiB 历史 | 7.914 → 7.943 ms（+0.4%） | 12.855 → 13.290 → 12.840 ms（−0.1%） |
| 64 个工具 | 2.609 → 2.492 ms（−4.5%） | 4.029 → 4.398 → 4.454 ms（+10.5%） |
| 约 1 MiB 图片 | 4.898 → 4.854 ms（−0.9%） | 7.156 → 7.263 → 7.299 ms（+2.0%） |

短请求信封 **1,669 → 1,139 B（−530 B，−31.8%）**，其余这三种负载同样各省 530 B。进程峰值 RSS 中位数 394,024 → 376,084 KiB（−4.6%，含 fixture）。首次重基计量的长历史 p95 +5.5%；加样本换核复测后长历史持平，但 64 工具 p95 +10.5%。各独立组尾延迟也有明显波动，不能以 p50 或减少的步骤替代尾延迟门槛。**结构简化和样本等价成立，整体性能门槛未通过；只提交草稿，不建议切换或部署。**
