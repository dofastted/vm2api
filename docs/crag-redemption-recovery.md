# CRAG 宿主兑换恢复

普通宿主兑换和设备订单应用在联系授权服务前，先写入私有 `redeem.json`。
新记录保存宿主 ID、原使用券、当前可信发行包摘要、原请求的精确 enrollment
选择器和发行者公钥 ID；字段集合严格校验，文件读取上限为 1024 字节。
enrollment 只能是空对象，或完整的 `issuer_public_key_id` / `payload_key_id` 对。
这些私有记录和凭据不得写入公开日志或 issue。

如果兑换提交后发行包发生变化，普通恢复返回
`crag_subscription_host_package_changed`。管理员明确确认后，可以提交：

```http
POST /api/panel/crag-subscription/recover
Content-Type: application/json

{"use_current_package":true}
```

新格式记录的恢复先验证当前发行包及原发行者身份，再原子更新当前包摘要。
原使用券、宿主凭据、enrollment 保持不变，随后重放原兑换请求。只有该兑换
请求返回的签名权益通过验证，才确认此券已应用；通用宿主状态不能证明某笔
订单已到账。默认恢复不会跨包改写摘要，发行者变化或不完整的选择器会明确拒绝。

旧格式记录没有保存 enrollment，无法可靠重建旧请求。它们只有在没有本地
权益、授权服务明确返回宿主 `not_found` 时，才允许显式使用当前可信包重试。
如果远端或本地已有权益，返回 `crag_subscription_recovery_unverified` 并保留原
记录，交由管理员核对。授权服务超时同样保留记录。
重放时的拒绝也不能否定首次请求可能已经成功，因此保留未完成记录和原请求
证据；只有首次请求收到明确拒绝时，才按该次失败结束兑换。

兑换成功按以下顺序持久化：签名权益、私有已兑换 receipt、清除未完成记录。
receipt 只保存使用券 SHA-256、宿主身份和已验证权益快照，不保存原使用券。
订单可用该 receipt 校正显示状态。receipt 已保存时，恢复不会再提交兑换；
权益已保存但 receipt 尚未保存时，重放同券请求补全确认。损坏的 receipt
不会被当作“未兑换”忽略，而是返回明确错误。

设备订单在提交兑换前，把原券摘要持久化到 `crag_shop_orders.redemption_sha256`。
列表、详情及重复应用只根据同一摘要对应的有效 receipt 修正订单到账状态；
没有摘要关联的历史订单，需要先在原订单点击应用建立关联。并发请求领取到
不同使用券时，条件更新失败会阻止后一个请求继续兑换。浏览器超时只查询
原订单，不自动重新提交应用请求。

额度到账后，管理员在内核页选择槽位及 CRAG 发行包。候选许可与新包不匹配
时，可选择“迁移授权并安装”，确认后提交固定发行版本和 `reissue: true`。
安装前以可信候选包验证并换签该槽授权；普通读取仍严格验证已安装包，残缺
目录不会被静默视为可用安装。授权或版本校验失败时，安装流程在停止槽位前
明确返回错误。
